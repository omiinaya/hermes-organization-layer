# Design

## Problem

A long-lived Hermes instance accumulates stray files: ad-hoc scripts, half-finished
experiments, cloned repos, notes, downloads. Without a convention, nothing is findable,
nothing ages out, and the workspace rots into a junk drawer.

## Concept

An **organization layer** = workspace convention + index + hygiene + agent tooling:

1. **Workspace convention** — a canonical cross-platform layout (`projects/`,
   `test-scripts/`, `scratch/`, `data/`, `notes/`, `docs/`, `assets/`, `_archive/`) so
   every artifact has a home by kind.
2. **Index** — `INDEX.md` (human) + `index.json` (machine) generated by scanning the
   workspace: what exists, where, purpose, tags, status, last activity. Hidden and
   dependency dirs are never indexed. Relative paths only — portable and public-safe.
   Each entry also records **virtual environments** (path + Python version, auto-detected
   from `pyvenv.cfg`, overridable via `.org.json`) so the correct interpreter is always
   obvious.
3. **Metadata** — each entry carries `.org.json` (name, kind, purpose, tags, status,
   entry_points). The index is derived from these plus the filesystem; it never guesses.
4. **Hygiene** — policy-driven: `flag` (default) marks `stale` (>90d idle) and
   `expired-scratch` (>30d) entries in the index without touching them; `auto` plus
   `prune --apply` archives candidates into `_archive/` as tarballs. Deletion is always
   explicit.
5. **Agent tooling** — a Hermes plugin exposes `/org` slash commands and `org_*` agent
   tools so the agent itself routes work into the right folders and refreshes the index
   as part of its normal workflow (clone -> projects/, scratch script -> test-scripts/,
   session end -> index).

## Decisions (locked with the user)

- **Cross-platform everywhere**: Windows/macOS/Linux for this and every app/plugin/dashboard.
- **Platform-default workspace root**: `%USERPROFILE%\Documents\hermes-org` (Windows),
  `~/Documents/hermes-org` (macOS/Linux, falling back to `~/hermes-org`), overridable via
  `HERMES_ORG_WORKSPACE` or `.org/config.json`.
- **English only** in all UI, docs, messages, and metadata.
- **Stale policy**: both `flag` and `auto` implemented; default is `flag` while we test
  and perfect the behavior.
- **Metadata format**: `.org.json` (structured, diffable, no parser dependency).
- **Scope**: plugin-integrated from the start (core library + Hermes plugin in one repo).

## Cross-platform notes

- Core (`orgcore/`) is pure Python stdlib: `pathlib`, `json`, `tarfile`, `shutil`,
  `fnmatch`, `datetime`. No shell, no YAML parser dependency, no OS-specific calls.
- Paths are always built with `pathlib`; never hardcode `/` or `\`.
- `default_workspace_root()` resolves per-OS and honors `HERMES_ORG_WORKSPACE`.

## Public-readiness (planned)

- Index privacy enforced, not just claimed: default `privacy: strict` means the
  index artifacts never contain an absolute machine path (workspace root is
  emitted as basename only); a regression test guards this invariant.
- Per-entry paths are relative; no secrets ever stored. `full` privacy mode exists
  only for explicit local debugging.
- Config is a documented JSON file; example in `workspace-skel/` (incl. a
  `.gitignore.example` template for git-backed workspaces).
- Tests (pytest) cover core behavior; English-only strings.
- MIT license; CHANGELOG kept; repo renamed/visible when public.
